# Temporary HTTP feature audit (1.8.0)

Scope: the new HTTP service, native page, firewall integration and lifetime, public serving boundaries, packaging, and regression checks. The user explicitly requested access from external networks.

- Kestrel binds IPv4 Any and IPv6 Any (when supported) using exclusive sockets. An occupied port fails startup; failure binding the second address family disposes the first listener. No URL ACL, external interpreter, or subprocess server is installed.
- Firewall rules have per-instance GUID names and restrict inbound TCP to the selected port and hosting executable, on all profiles and from any remote address. Stop/restart/normal exit remove only that instance's rule. Failed or partial additions roll back; cleanup failures remain retryable. Existing user rules are not changed.
- A folder must be explicitly selected and exist. GET/HEAD serve regular files; other write methods are rejected. CORS is opt-in and does not grant credentialed requests. Directory-listing names are HTML encoded and links are URL encoded. No application-control API is exposed.
- Request resolution rejects traversal, backslashes, control characters, NTFS alternate streams, Windows trailing-space/dot aliases, and symbolic links/junctions. On Windows, the final path of the **opened file handle** must remain beneath the root, preventing a link replacement between path validation and file opening from leaking outside file contents.
- File bodies are streamed rather than buffered in memory. Connections, request header time, idle connection time, and request body size are bounded. Listings display up to 1000 entries. The service has no access to user-supplied executable commands.
- Public files are deliberately unauthenticated over plain HTTP. The page states this and distinguishes local/interface IPs from public IPs. NAT, port forwarding, cloud security groups, and CGNAT remain external configuration; public reachability is not claimed from a local test.
- Normal shutdown has a bounded drain interval. Process kill, machine crash, or power loss can leave an application-scoped allow rule; the listener disappears with the process. The usage guide names the residual rules and how to remove them.
- ASP.NET Core comes from the .NET 8 shared framework and is included in self-contained publications. No new third-party NuGet package is introduced. Runtime servicing comes from the .NET SDK used by the workflow; native library/resource/license checks remain part of release verification.

Evidence: service tests exercise real sockets and HTTP requests, lifecycle/restart, IPv4/IPv6 bind failure, content types, HEAD, CORS, traversal/link prevention, final-handle boundaries, and firewall failure rollback/retry. Windows integration verifies a real all-profile firewall rule, HTTP access via a host interface, and cleanup. Packaged GUI tests cover all 14 pages (168 layout/theme/language combinations), native button invocation for HTTP Start/Restart/Stop, serving, navigation, language switching, and cleanup.

Limits: this is a static file service, not a Python/Node/PHP host. Public-internet reachability, native directory-picker and Explorer/browser interaction, x86/ARM64 hardware execution, and adversarial local filesystem mutation require environment-specific/manual acceptance. The selected folder should be controlled by its owner while being shared. This review is not a penetration test.
